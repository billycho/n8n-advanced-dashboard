# 🧠 1. `users`

(You said only 1 admin for now, but design it properly)

| Field     | Type            | Description            |
| --------- | --------------- | ---------------------- |
| _id       | ObjectId        | Primary key            |
| name      | String          | Admin name             |
| email     | String (unique) | Login email            |
| password  | String (hashed) | Auth password          |
| role      | String          | "admin" (future-proof) |
| createdAt | Date            | Created timestamp      |
| updatedAt | Date            | Updated timestamp      |

# ⚙️ 2. `settings`

(Global app settings – 1 document only)

| Field                     | Type     | Description         |
| ------------------------- | -------- | ------------------- |

# 🤖 3. `agents`

(Main AI Agent config)

| Field       | Type     | Description                    |
| ----------- | -------- | ------------------------------ |
| _id         | ObjectId | Primary key                    |
| name        | String   | Agent name                     |
| description | String   | Optional                       |
| isEnabled   | Boolean  | Enable / Disable               |
| schedule    | String   | Cron format (e.g. "0 8 * * *") |
| parameters  | Object   | Dynamic JSON config            |
| createdBy   | ObjectId | User reference                 |
| createdAt   | Date     | Created timestamp              |
| updatedAt   | Date     | Updated timestamp              |

👉 Example `parameters`:

```json
{
  "model": "gpt-4",
  "temperature": 0.7,
  "prompt": "Summarize today's logs"
}
```

# 🔗 Relationships (Simple View)

* `users` → owns → `agents`
* `agents` → generates → `agent_logs`
* `agent_logs` → aggregated → `daily_reports`
* `settings` → controls → notifications
* `notifications` → triggered by → logs / reports

---

# 🧠 Design Notes (Important)

### 1. Why `parameters` is flexible JSON

Because:

* Each AI agent can have different configs
* You avoid schema changes later
* Perfect for AI systems

---

### 2. Why separate `logs` and `reports`

* Logs = raw data (every run)
* Reports = summarized (daily insight)

👉 This is how real AI systems scale

---

### 3. Why `schedule` is string (cron)

Simple and powerful:

* `"0 * * * *"` → every hour
* `"0 8 * * *"` → every day at 8 AM

---

### 4. Why `notifications` is separate

So later you can:

* Add UI notifications 🔔
* Retry failed emails
* Track history
